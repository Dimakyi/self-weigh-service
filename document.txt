# Self-Weigh Service — Temporary Polish Backlog

**Status:** Outstanding improvements  
**Purpose:** Track technical issues and areas that need further refinement before considering the project more complete.

## 1. Outbox lease duration and batch processing

**Issue**

- Each Kafka send can wait up to 10 seconds.
- The worker processes batches of up to 100 events under a 60-second lease.
- If Kafka is unavailable, the lease may expire before the entire batch has been processed.
- Remaining events may not have their failures recorded correctly, and events may be sent more than once.

**Possible improvements**

- Reduce the worker batch size.
- Increase the lease duration.
- Implement lease renewal while processing a batch.

**Validation needed**

- Test with Kafka unavailable for longer than the current lease duration.
- Confirm that failed events are recorded correctly.
- Confirm that events can be reclaimed and retried safely.

## 2. Kafka producer timeouts and duplicate delivery

**Issue**

A send that times out may remain queued in the producer and be delivered later. This can result in duplicate event delivery.

**Required improvement**

Ensure downstream consumers handle repeated events safely by checking event IDs and skipping events that have already been processed.

**Validation needed**

- Simulate a producer timeout.
- Verify that duplicate event IDs are not processed twice by consumers.
- Confirm that legitimate new events are still processed.

**Important:** The system uses at-least-once delivery. Duplicate delivery must be handled through consumer-side idempotency rather than assuming exactly-once delivery.

## 3. Docker startup dependencies

**Issue**

The worker starts as soon as the API container starts, rather than waiting for the API to become healthy.

This creates a possibility that the worker starts before database migrations have completed.

**Possible improvement**

- Add a health check to the API service.
- Review Docker Compose startup dependencies.
- Ensure dependent services wait for the required health conditions.

**Validation needed**

- Start the application from a fresh environment.
- Confirm the worker does not begin processing before the required services are ready.
- Confirm normal startup and recovery behaviour.
